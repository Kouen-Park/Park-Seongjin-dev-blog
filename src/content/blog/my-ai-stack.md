지난 글에서는 요즘 넘쳐나는 코딩 AI들을 한번 정리해봤습니다.

Cursor와 OpenCode는 뭐가 다른지,

DeepSeek이나 Llama 같은 오픈웨이트 모델은 무엇인지,

AI 에디터와 코딩 에이전트는 또 어떻게 다른지까지 살펴봤습니다.

그렇게 열심히 분류하고 나니 자연스럽게 다음 질문이 생겼습니다.

> "그래서 나는 실제로 뭘 쓰고 있지?"

한번 세어봤습니다.

ChatGPT, Claude, Cursor, Copilot, Perplexity, Antigravity, OpenCode, Higgsfield...

**그만 세기로 했습니다.**

분명 처음에는 ChatGPT 하나였던 것 같은데 어느 순간 Applications 폴더가 AI 스타트업 박람회장이 되어 있었습니다.

그래도 다행히 이 모든 걸 매일 동시에 사용하는 것은 아닙니다.

이것저것 설치하고,

무료 크레딧도 받아보고,

새 모델이 나왔다고 하면 기웃거려보고,

체험 기간이 끝나면 조용히 보내주기도 하면서

지금은 어느 정도 **각자의 역할이 정해졌습니다.**

## 지금 내 AI 스택

현재 사용하는 방식을 대충 그려보면 이렇습니다.

```text
                   My AI Stack
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
      Main AI          Coding         Research
 ChatGPT / Claude      Cursor        Perplexity
        │               │
   성능에 따라          └─ Copilot / Antigravity
   구독 변경                  (백업)
                        │
                        ▼
                    Experiment
               OpenCode + Local LLM

                    Creative
                   Higgsfield
                     + etc.
```

써놓고 보니 꽤 그럴듯합니다.

실제로 사용할 때는 이것보다 조금 덜 체계적입니다.

가끔 그냥 **먼저 눈에 들어오는 앱을 엽니다.**

## ChatGPT vs Claude — 이기는 팀 우리 팀

가장 많이 사용하는 AI는 결국 **ChatGPT와 Claude**입니다.

그런데 한쪽을 무조건 메인으로 정해두지는 않습니다.

학생이기에 둘 다 구독하긴 부담이 됩니다.

새로운 모델이 나오면 성능을 확인하고,

사람들의 평가가 Claude가 낫다고 하면 Claude를 쓰고,

새로운 GPT가 더 마음에 들면 ChatGPT로 구독합니다.

하지도 않던 X 계정을 만든 이유도 티보 리셋 확인 겸 사람들 평가 확인용 입니다.

현재는 Astra의 출시로 ChatGPT 구독을 하고 있는데,

Claude에서 Opus 5.5 출시 반응이 핫해서 옮길까 생각중 입니다.

그만큼 상당히 냉정한 관계입니다.

> **이기는 팀이 우리 팀입니다.**

코딩 성능만 보는 것도 아닙니다.

긴 문맥을 얼마나 잘 처리하는지,

설명을 얼마나 이해하기 쉽게 하는지,

도구를 얼마나 잘 사용하는지,

그리고 아주 중요하게

**사용량을 얼마나 주는지**도 봅니다.

아무리 똑똑해도 오후 3시에

> "You've reached your usage limit."

이라고 하면 그날의 우정은 거기까지입니다.

그래서 ChatGPT와 Claude는 프로젝트 설계, 기술 비교, 디버깅, 공부, 글쓰기 등 거의 모든 곳에서 사용하지만,

어느 하나에 완전히 정착했다기보다는 **모델 업데이트에 따라 왔다 갔다 하는 편**입니다.

## Cursor — 말은 여기까지, 이제 코드 짜자

개인 프로젝트를 개발할 때 메인 IDE는 **Cursor**입니다.

ChatGPT나 Claude에서는 주로

> "이걸 어떻게 만들까?"

를 고민합니다.

아키텍처를 생각하고,

어떤 라이브러리를 사용할지 비교하고,

문제가 생기면 원인을 같이 찾아봅니다.

그러다 어느 정도 방향이 정해지면 Cursor를 엽니다.

여기서부터 실제 코드가 만들어집니다.

프로젝트 전체를 열어놓고 직접 코드를 작성하면서 필요한 부분은 AI에게 맡기는 방식이 현재 저한테 가장 잘 맞습니다.

에이전트에게 모든 것을 넘겨버리는 것보다 제가 코드를 계속 읽으면서 작업할 수 있다는 점도 좋아합니다.

AI가 코드를 아무리 잘 작성해도 결국 최소한

> "이거 뭔가 이상한데?"

정도는 제가 알아차릴 수 있어야 한다고 생각합니다.

왜 이상한지는 다시 AI에게 물어보면 됩니다.

**역할 분담이 아주 명확합니다.**

## 학교에서는 VS Code

여기서 잠깐 **AI가 아닌 친구**도 하나 등장합니다.

학교 과제를 할 때는 Cursor보다 **VS Code**를 더 많이 사용합니다.

물론 VS Code 자체는 AI 도구가 아닙니다.

이 글은 제가 사용하는 AI 도구들을 정리하는 글이지만, 실제로 AI를 **어떤 개발 환경에서 사용하는지**까지 설명하려다 보니 잠시 끼어들었습니다.

수업 환경에 맞추기도 편하고,

과제에서는 제가 직접 구현하고 이해해야 하는 부분이 많기 때문입니다.

그래서 개발 환경만 놓고 보면 자연스럽게 이렇게 나뉘었습니다.

```text
개인 프로젝트
→ Cursor

학교 / 과제
→ VS Code
```

개인 프로젝트에서는

> "이거 구현해줘."

라고 하다가,

학교 과제에서는 다시 직접 키보드를 잡습니다.

**시험볼때는 Cursor가 옆에 앉아주지 않기 때문입니다.**

## Copilot과 Antigravity — 벤치의 중요성

GitHub Copilot과 Antigravity도 사용합니다.

다만 현재 메인 선수는 아닙니다.

둘 다 학생 혜택으로 사용할 수 있기 때문에 **백업 역할**이 큽니다.

ChatGPT나 Claude 사용량이 부족하거나,

다른 에이전트가 필요한 상황에서 꺼냅니다.

대략 이런 느낌입니다.

```text
ChatGPT / Claude
      │
      │ 사용량 소진
      ▼
"아 맞다, 나 학생이지."
      │
      ▼
Copilot / Antigravity
```

학생 신분의 장점입니다.

과제는 늘어나지만 AI 사용량도 늘어납니다.

**완벽한 등가교환은 아니지만 일단 받을 수 있는건 다 받습니다.**

Copilot은 특히 IDE 안에서 자동완성을 받을 때 자연스럽게 사용할 수 있어서 굳이 매번 새로운 채팅을 열 필요가 없다는 점이 편합니다.

메인 AI들이 결근하면 들어오는 **대타** 정도로 생각하고 있습니다.

## 요즘 새 장난감 — OpenCode + Local LLM

최근 가장 관심 있는 분야는 **로컬 LLM**입니다.

지금까지는 대부분 GPT나 Claude처럼 다른 회사의 서버에서 돌아가는 모델을 사용했습니다.

그런데 Llama, Qwen, DeepSeek 같은 오픈웨이트 모델들을 보다 보니 자연스럽게 생각이 하나 들었습니다.

> "굳이 남의 컴퓨터에서만 돌려야 하나?"

그래서 요즘 **OpenCode**를 가지고 이것저것 실험하고 있습니다.

OpenCode가 재미있는 이유 중 하나는 도구와 모델을 분리해서 생각할 수 있다는 점입니다.

```text
OpenCode
   │
   ├── Claude
   ├── GPT
   ├── Qwen
   ├── DeepSeek
   └── Local LLM
```

OpenCode라는 작업 환경은 그대로 두고 뒤에서 일하는 모델을 바꿀 수 있습니다.

특히 모델까지 로컬에서 돌리면 코드와 프롬프트를 외부 모델 제공자에게 보내지 않는 환경도 구성할 수 있습니다.

이론적으로 상당히 매력적입니다.

문제는 제 컴퓨터가 **똥컴**이란 점입니다.

오픈웨이트 모델에 관심을 가지기 시작하면서 새로운 단위도 많이 배우고 있습니다.

파라미터 수,

양자화,

메모리 사용량,

토큰 속도...

그리고 가장 중요한 단위가 하나 더 있습니다.

**인내심입니다.**

모델이 돌아간다는 것과 쾌적하게 돌아간다는 것은 전혀 다른 문제였습니다.

그래도 직접 모델을 바꿔보고,

OpenCode에 연결해보고,

어디까지 로컬에서 처리할 수 있는지 확인하는 과정 자체가 꽤 재미있습니다.

아직 Cursor를 대체할 정도의 메인 환경은 아니고,

현재는 **새 장난감을 발견한 개발자의 실험실**에 가깝습니다.

조금 위험한 상태입니다.

보통 이런 상태에서 새로운 프로젝트가 하나 더 생깁니다.

## 조사할 때는 Perplexity

자료 조사는 주로 **Perplexity**를 사용합니다.

특히 최신 AI 서비스,

새로운 개발 도구,

라이브러리 비교,

가격이나 정책처럼 계속 바뀌는 정보를 찾아야 할 때 먼저 열어보는 편입니다.

역할을 단순하게 나누면 이렇습니다.

```text
"이걸 어떻게 생각하지?"
→ ChatGPT / Claude

"실제로 지금 어떻게 되어 있지?"
→ Perplexity
```

물론 Perplexity가 출처를 보여준다고 해서 그대로 믿지는 않습니다.

중요한 내용은 원문을 다시 확인합니다.

AI가 검색 시간을 줄여줄 수는 있지만,

**인터넷이 갑자기 정직해지는 기능까지 제공하지는 않습니다.**

그래도 예전처럼 검색 결과 열 개를 열어놓고 어디서 봤는지 잊어버리는 일은 많이 줄었습니다.

이제는 탭 대신 AI 답변을 의심하면 됩니다.

## 이미지와 영상은 Higgsfield 같은 생성형 AI

코드와 조사 외에도 AI를 사용합니다.

대표적으로 **Higgsfield** 같은 이미지·영상 생성 AI입니다.

프로젝트 비주얼을 만들거나,

블로그 Hero Image 아이디어를 잡거나,

영상이나 이미지를 만들어보고 싶을 때 이런 도구들을 사용합니다.

이쪽은 ChatGPT나 Claude와는 완전히 다른 역할입니다.

```text
🧠 생각
ChatGPT / Claude

💻 개발
Cursor / OpenCode

🔎 조사
Perplexity

🎨 이미지 / 영상
Higgsfield + 기타 생성형 AI
```

이쯤 되면 AI 하나를 사용하는 게 아니라 **AI 팀을 운영하는 느낌**이 들기도 합니다.

차이가 있다면 직원들이 월급 대신 토큰을 먹습니다.

그리고 가끔 이유 없이 일을 멈춥니다.

생각해보니 꽤 비슷합니다.

## Manus와 Kiro — 한때는 우리도 함께였다

반대로 사용해봤지만 현재는 거의 사용하지 않는 도구들도 있습니다.

대표적으로 **Manus와 Kiro**입니다.

새로운 서비스가 나오거나 이벤트가 있을 때 궁금해서 사용해봤습니다.

무료 크레딧도 있고,

새로운 기능도 있고,

무엇보다

> "이건 또 뭐지?"

라는 궁금증이 있습니다.

개발자에게 상당히 위험한 세 단어입니다.

사용해보면서 새로운 에이전트가 어떻게 동작하는지 경험하기에는 재미있었지만,

이벤트가 끝난 뒤에도 계속 메인 워크플로우에 남을 정도로 사용하지는 않았습니다.

예전에는 새로운 AI를 발견하면

> "어디에 써야 하지?"

부터 생각했다면,

요즘은 반대로 생각합니다.

> "지금 쓰는 것보다 뭘 더 잘하지?"

딱히 답이 없다면 굳이 추가하지 않습니다.

Applications 폴더에도 복지가 필요합니다.

## 결국 지금은 이렇게 쓴다

현재 실제 사용 방식을 최대한 단순하게 만들면 이렇습니다.

```text
🧠 생각 / 설계 / 공부
ChatGPT ↔ Claude
     ↑
모델 성능에 따라 메인 구독 변경


💻 개인 개발
Cursor


🛟 백업
GitHub Copilot / Antigravity


🔬 요즘 실험 중
OpenCode + Local LLM


🔎 조사
Perplexity


🎨 이미지 / 영상
Higgsfield + 기타 생성형 AI


📦 사용해봄 / 현재는 거의 안 씀
Manus / Kiro / 기타 AI
```

써놓고 보니 여전히 많습니다.

하지만 예전과 달라진 점이 하나 있습니다.

**적어도 왜 설치했는지는 알고 있습니다.**

대부분은요.

## AI를 많이 쓰는 것과 잘 쓰는 것은 다르다

처음에는 새로운 AI가 나오면 일단 사용해보고 싶었습니다.

지금도 그렇습니다.

아마 이건 쉽게 안 고쳐질 것 같습니다.

하지만 이것저것 사용해보면서 한 가지는 확실히 느꼈습니다.

> **AI 도구가 많다고 생산성이 자동으로 올라가는 것은 아니다.**

잘못하면 이런 일이 벌어집니다.

```text
ChatGPT에게 질문
       ↓
Claude 의견도 궁금함
       ↓
Perplexity로 팩트체크
       ↓
Cursor에게 구현시킴
       ↓
OpenCode라면 어떻게 하나 궁금함
       ↓
같은 작업 다시 시킴
       ↓
결과 비교
       ↓
45분 지남
       ↓
Git status
       ↓
변경 사항 없음
```

완벽한 AI 워크플로우입니다.

**워크만 있고 플로우가 없습니다.**

그래서 요즘은 새로운 AI를 발견하면 먼저 한 가지를 생각합니다.

> "이게 지금 쓰는 도구보다 무엇을 더 잘하지?"

답이 있다면 사용해봅니다.

없다면 일단 지나갑니다.

물론 며칠 뒤 다시 찾아볼 수도 있습니다.

사람은 쉽게 변하지 않습니다.

결국 지금 제 AI 환경은 **최고의 AI 하나를 찾는 방식**보다는

**각 작업에 잘 맞는 AI를 골라 쓰는 방식**에 가까워졌습니다.

생각하고 정리할 때는 ChatGPT나 Claude,

개발할 때는 Cursor,

조사할 때는 Perplexity,

이미지와 영상이 필요하면 Higgsfield 같은 생성형 AI,

그리고 요즘은 그 옆에서 OpenCode와 로컬 LLM을 만져보고 있습니다.

아마 몇 달 뒤에는 이 목록도 또 달라져 있을 겁니다.

AI 업계에서 6개월이면 꽤 긴 시간입니다.

이 글을 다시 읽는 미래의 제가

> "와, 그때는 저걸 썼네."

라고 할 수도 있습니다.

아니면 여전히 같은 도구를 사용하고 있을 수도 있습니다.

다만 한 가지는 꽤 확실합니다.

**그때도 뭔가 하나는 새로 설치하고 있을 것 같습니다.**
